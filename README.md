# legal-writing-samples

[![tests](https://github.com/liujunchao-nju/legal-writing-samples/actions/workflows/tests.yml/badge.svg)](https://github.com/liujunchao-nju/legal-writing-samples/actions/workflows/tests.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

中文法律文书范文库：六类常见文书的要素模型与写作大纲，六篇基于公开案例改写的范文（逐篇标注参照案号），以及一个把条号引用纳入自动校验的检查工具。

## 为什么做这个

学写法律文书，通常有两条路：看教材上的结构说明，或者读法院公开的裁判文书。前者抽象，后者是结果而非过程，中间那一步「一份合格的文书究竟长什么样、为什么这么写」反而最难找。

这个仓库做三件事。

第一，把每类文书的**要素**拆出来。起诉状该写哪几项、答辩状该先说什么、再审申请书为什么必须落到法定事由，都写成可加载的清单。配套一个校验命令，把写好的文书过一遍，缺什么一目了然。

第二，范文都基于**公开案例**改写，并在文首标注参照的案号与来源。不是凭空编的例子，而是真实纠纷里的文书形态。两篇范文参照同一案件的对向立场（同一买卖合同纠纷的起诉状与答辩状），另两篇参照同一案件的两个阶段（劳动仲裁申请书与上诉状），方便对照攻防与程序的推进。

第三，文书的法条引用**可校验**。范文正文里出现的条号，会被拿去与经核验的法条库比对，出现未登记或已过时的条号，测试会直接失败。

## 安装

```bash
pip install -e .
```

只依赖 `PyYAML`。Python 3.9 及以上。

## 用法

```bash
# 列出文书类型与范文
lws list

# 查看某类文书的定义与依据
lws show --type complaint

# 查看某篇范文全文（含参照案号）
lws show --sample 05

# 生成写作大纲（结构可填的骨架）
lws outline --type appeal --out 上诉状大纲.md

# 校验一份文书的要素是否齐备
lws check --type complaint --file 我的起诉状.md
lws check --sample 01          # 也可以校验范文自身
lws check --type complaint --file 我的起诉状.md --markdown --out 校验报告.md

# 查看法条库，或某一条的原文
lws laws
lws laws --key 民事诉讼法第172条

# 校验全部数据文件的结构与条号引用
lws verify
```

`check` 只做提醒不判分：关键词没命中的要素，可能只是换了表述。它的用处是把「整类要素漏写」挡在交付之前。

Python API：

```python
from lws import check_document, list_samples, load_laws, render_outline

print(render_outline("retrial"))                       # 写作大纲
result = check_document("complaint", open("起诉状.md", encoding="utf-8").read())
print(result["missing_required"])                      # 缺失的必备要素
print(load_laws()["民事诉讼法第172条"]["text"])         # 取回条文原文
print([s["reference"]["case_id"] for s in list_samples()])
```

## 支持的文书类型

| 类型标识 | 名称 | 分类 | 主要依据 |
| --- | --- | --- | --- |
| `complaint` | 民事起诉状 | 民事诉讼文书 | 民事诉讼法第 122 条、第 124 条 |
| `defense` | 民事答辩状 | 民事诉讼文书 | 民事诉讼法第 128 条 |
| `arbitration` | 劳动争议仲裁申请书 | 劳动争议文书 | 劳动争议调解仲裁法第 2 条、第 5 条、第 27 条 |
| `appeal` | 民事上诉状 | 民事诉讼文书 | 民事诉讼法第 171 条、第 172 条 |
| `retrial` | 民事再审申请书 | 民事诉讼文书 | 民事诉讼法第 210 条、第 214 条、第 216 条 |
| `defense-speech` | 刑事辩护词 | 刑事诉讼文书 | 刑事诉讼法第 37 条、刑法第 27 条、第 67 条 |

新增一类文书不需要改代码，在 `lws/data/documents/` 下加一个 YAML 文件即可。

## 条号核验

`lws/data/laws.yaml` 是唯一合法的引用来源，收录 23 条现行有效条文，覆盖民事诉讼法、民事诉讼法司法解释、劳动争议调解仲裁法、刑法、刑事诉讼法与民法典合同通则。每条都记录了核验日期与来源。

文书要素里的 `basis` 引用必须以 key 形式命中该文件；范文正文里以汉字写成的条号，会被提取出来与条号清单比对。两条路径任一出现未登记条号，`lws verify` 与单元测试都会失败。

这里有一个容易踩的坑：**民事诉讼法在 2023 年修正后条号整体位移**。上诉状应当包括的内容由原第 165 条移至**第 172 条**，当事人申请再审由原第 205 条移至**第 210 条**。若按条文数量的位移去推算条号，会分别错写成第 168 条（实为小额诉讼审限）与第 206 条（实为调解协议司法确认）。本仓库一律以现行条文号为准，并在条号解析中对合同条款的「第×条」做了排除，避免把《商品房预售合同》第三十条误判为法条。

## 数据文件

```
lws/data/
  laws.yaml               经核验的法条库（引用白名单）
  documents/
    complaint.yaml        起诉状的要素模型
    defense.yaml          答辩状
    arbitration.yaml      劳动仲裁申请书
    appeal.yaml           上诉状
    retrial.yaml          再审申请书
    defense-speech.yaml   刑事辩护词
  samples/
    01-complaint-sales.md       范文（含 front matter 来源标注）
    ...
```

每份文书类型包含：`legal_basis`（主要依据）、`structure`（结构顺序）、`elements`（要素清单，带必备与否、命中关键词、依据与说明）、`tips`（写作要点）。

## 范文的来源与改写说明

范文的事实、金额与争议焦点取自公开的人民法院案例库参考案例与最高人民法院指导性案例。改写遵循三条做法：

1. 当事人名称沿用原案例的脱敏写法（如「某科技公司」「李某」），不使用真实主体名称，也不补充原案例未公开的个人信息；
2. 金额、时间、案号等关键事实保留原表述，不作修改，以便读者按编号回查；
3. 每篇范文的写作要点中，说明该案最终的裁判结果与理由，明确指出范文中的主张哪些被采纳、哪些没有，避免给人「照着写就能赢」的误解。例如 03 与 04 所参照的案件，法院最终认定网络主播与公司之间不构成劳动关系，范文的写作要点里写明了这一结果与三点理由。

## 开发

```bash
pip install -e ".[dev]"
python -m pytest -q
```

测试覆盖法条库结构与中文条号解析、文书要素校验、范文来源标注与自检通过率、命令行接口。其中两条是质量闸门：`test_every_sample_passes_its_own_check` 要求每篇范文都能通过其所属类型的要素校验；`validate_all` 要求每处法条引用都能在法条库中找到。

## 免责声明

本仓库提供范文、要素清单与校验工具，不构成法律意见。范文是基于公开案例的改写示例，当事人、金额与情节均按脱敏与教学目的处理，不得直接套用于具体案件。文书格式与管辖要求可能因地区与审级而异，正式文书请以受诉机关的要求为准，涉及重大利益的案件应咨询执业律师。
